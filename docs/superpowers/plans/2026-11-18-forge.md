# The Forge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Custom Run modifier, The Forge: fusing two copies at a rest site raises a card past +1 (up to +9), and the merchant sells +0 copies of deck cards.

**Architecture:** Pure arithmetic (fusion level, caps, prices, curve table parsing) lives in `src/Core/ForgeRule.cs`.
Upgrade levels use the game's own `CurrentUpgradeLevel`. Harmony patches on `CardModel` raise the max and gate
ordinary upgrades. They also replay the +1 curve at every higher level, and let saved levels above 1 load. The rest
option and the merchant service reuse vanilla deck selection, which is already synced in co-op.

**Tech Stack:** C# .NET 9, Harmony, Godot 4.5.1, xUnit; Python 3 (Podman `slayspoon-tools`) for the review page.

**Spec:** `docs/superpowers/specs/2026-11-18-forge-design.md`

## Global Constraints

- Max level 9; result level = kept + sacrificed + 1, clamped to the card's cap.
- Only Fuse goes past +1; ordinary upgrades stop at +1. Cards whose class overrides `MaxUpgradeLevel` (curses at 0,
  StS1 Searing Blow) are never touched by the Forge.
- Duplicate price: Basic/Common 25, Uncommon 50, Rare and anything else 75; Ascension 6+ adds 25 to each; +25 per earlier
  purchase (per player, whole run, saved). One per merchant visit. The copy is +0. Curses and Status cards are excluded.
- Costs never go below 0; keywords are never applied twice.
- Every text in EN and FR. No decompiled code committed (the review tool writes ids and numbers only).

## Review Focus

- A saved run with a +5 card reloads, and a co-op client receives it: the level must load whether the modifier is known
  yet or not (load scope keyed on the saved level, not on the run state).
- Upgrading a +1 card through Armaments, Apotheosis or a relic in a Forge run does nothing; those paths do not offer it.
- A cost-only card fused past the level where its cost reaches 0 cannot happen (computed cap).
- Fusing then cancelling at the preview spends nothing: no card removed, rest action kept.
- A namesake pair fused into the other version keeps the level and the kept card's enchantment.

- `ForgeRule.MaxLevel = 9`
- `int FusedLevel(int kept, int sacrificed, int cap)`
- `bool CanFuseInto(int keptLevel, int cap, bool fusable)`: true when fusable and keptLevel < cap
- `int DuplicatePrice(ForgeRarity rarity, bool inflation, int purchases)`

- `IReadOnlyDictionary<string, ForgeCurve> ParseCurves(string json)`: throws `FormatException` on a cap outside 1–9
- `int CostCap(int costAfterFirst, int costDelta)`: levels a cost-only card can reach before cost 0 (delta < 0)

### Task 2: Level mechanics (Harmony)

**Files:** Create `src/Forge/ForgeLevels.cs`, `src/Forge/ForgeCurves.cs`; modify `src/SlaySpoon.csproj` (embed `data/forge/curves.json`).

- `ForgeCurves.For(string id) -> ForgeCurve?` reads the embedded table once.
- `ForgeLevels.Cap(CardModel)`: the table cap, else the computed cost cap for cost-only cards, else 9.
- Patches:
  - `get_MaxUpgradeLevel` postfix (base class only): Cap when the owner's run has `SpoonForge`, a load scope is open, or a fusion scope is open.
  - `IsUpgradable` postfix: false at level ≥ 1 for base-max cards, unless a fusion scope is open.
  - `FromSerializable` prefix/finalizer opens a load scope when the saved level is > 1.
  - `UpgradeInternal` prefix/postfix at level ≥ 1: snapshot cost, star cost and keywords, then restore them after.
    Apply the table `perLevel` (resetting vars to the snapshot first) and `CostPerLevel`; cost-only cards keep their delta.
