# Matriochka and Folie à deux Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the two owner-designed modes: Matriochka (Custom Run modifier) and Folie à deux (host card + Custom Run modifier).

**Architecture:** Each mode is a `ModifierModel` subclass in `src/Config/` whose vanilla hook overrides carry most of the
rules; pure decisions (which map row, who wins which stake) live in `src/Core/` with xUnit tests; Harmony patches only
where no hook exists (event options, reward screen proceed button, combat reward offer, host submenu).

**Tech Stack:** C# .NET 9, Harmony, Godot 4.5.1, xUnit; `make build`, `make test` (Podman).

**Spec:** `docs/superpowers/specs/2026-11-14-matriochka-design.md`, `docs/superpowers/specs/2026-11-14-folie-a-deux-design.md`

## Global Constraints

- Every added string in `godot/SlaySpoon/localization/eng/` and `fra/`; titles "Matriochka" and "Folie à deux" in both.
- Menu descriptions are one short sentence (owner, 2026-11-14): let players discover the rules.
- Never write the regular save; no extra draws on vanilla RNG streams (own `Rng(run.Rng.Seed, "<name>")` streams).
- Harmony: helper methods in patch classes must not be named `Prefix`, `Postfix`, `Transpiler`, `Finalizer`, `Prepare`.
- Saved properties reuse vanilla property names (see `SpoonCampfireGift.FurCoatCoordCols`).
- Build with 0 warnings; all xUnit + pytest pass.

## Review Focus

1. Co-op: every hook runs on every client; per-player rewards must be offered for every player (non-local ones only sync), as `CombatRoom.OfferRoomEndRewards` does.
2. Matriochka + vanilla Hoarder both ticked: copies must not stack (6 copies instead of 3).
3. Mandatory reward with an empty card reward (pool exhausted) must not soft-lock the rewards screen.
4. Folie à deux with a dead player: dead players get no stake and cast no bid.
5. Folie à deux in solo: no chest; vanilla rewards.

### Task 2: Matriochka modifier

**Files:**
- Create: `src/Config/MatriochkaModifier.cs` (`SpoonMatriochka`), `src/Matriochka/MatriochkaPatches.cs`
- Modify: `src/CustomRunUi/ModifierListPatch.cs`, `src/TopBar/TopBarPercentPatch.cs` (short label),
  `godot/SlaySpoon/localization/{eng,fra}/modifiers.json`

`SpoonMatriochka : ModifierModel` overrides:
- `AfterCardChangedPiles`: vanilla Hoarder's body (2 clones to the bottom of the deck, skip set); does nothing when the
  run also has vanilla `Hoarder`. `ShouldAllowMerchantCardRemoval` → false.
- `ModifyNextEvent`: act index 1, first event room of the act (no event of this act visited yet) → `ModelDb.Event<DollRoom>()`;
  act index 2 and current row == `ReflectionsRow` → `ModelDb.Event<Reflections>()`.
- `ModifyUnknownMapPointRoomTypes`: on the Reflections row, only `RoomType.Event`.
- `ModifyGeneratedMap(Late)`: act index 2, every point of the Reflections row becomes `MapPointType.Unknown`.
- `AfterRoomEntered`: `MerchantRoom` and no earlier merchant in the run → `RelicCmd.Obtain<DollysMirror>` for every
  player; `MerchantRoom`, `RestSiteRoom`, non-Ancient `EventRoom` → for every player, offer one 3-card reward of their
  character pool (`CardReward(options, 3, player) { CanSkip = false }` through
  `new RewardsSet(player).WithCustomRewards(..).WithSkippingDisallowed().Offer()`, run with `TaskHelper.RunSafely`).
- `TryModifyRewards`: combat and treasure rooms: a `CardReward` that cannot be skipped (set `CanSkip` false through its
  backing field; add one in treasure rooms).

Patches (`MatriochkaPatches.cs`): `DollRoom.GenerateInitialOptions` postfix → one option giving Bing Bong (the
event's `OptionFromChoice` with its Bing Bong entry); `Reflections.GenerateInitialOptions` postfix → only the Shatter
option; `NRewardsScreen.TryEnableProceedButton` prefix → keep the button disabled while an unclaimed `CardReward` with
cards remains on a Matriochka run.

Text: title "Matriochka"; EN "Hoard everything. Every floor brings cards." FR "Accumulez tout. Chaque étage apporte des cartes."; short "Matr.".

### Task 5: Folie à deux chest (sync + overlay) and combat rewards

**Files:**
- Create: `src/Folie/FolieChest.cs` (flow + sync), `src/Folie/FolieChestOverlay.cs` (view), `src/Folie/FolieRewardPatch.cs`

- `FolieChest.Run(IReadOnlyList<Player> players, IReadOnlyList<FolieStake> stakes, bool consolation) -> Task<List<FolieAward>>`:
  every client reserves a `PlayerChoiceSynchronizer` choice id for each living player in slot order; the local player
  picks in the overlay and syncs, the others are awaited concurrently; each arrival updates the overlay (bidder marker
  under the head). Fights use `RelicPickingResult.GenerateRelicFight` semantics on `Rng(run seed, "SlaySpoonFolie_<floor>_<n>")`
  and the overlay animates the rounds. Solo: returns each stake to its owner without a chest.
- `FolieRewardPatch`: prefix on `CombatRoom.OfferRoomEndRewards` (and `TreasureRoom.DoExtraRewardsIfNeeded`): generate
  every player's set, pull the `CardReward`s, run the chest with one stake per player (its first card reward), rebuild
  each winner's reward as `new CardReward(cards recreated for the winner, CardCreationSource.Other, winner, options)`
  added to the winner's set, then offer the sets as vanilla.
- [ ] `make build`, commit.
